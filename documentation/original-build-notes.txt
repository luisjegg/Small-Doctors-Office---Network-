Note Why every switch needs the vlans configed
- Every switch needs to know the vlans that are in the network, if for whatever reason traffic passes through them they need to have that vlan 802.1q tag in their data base if not they wont pass the traffic along they would just drop the frame. They do not route traffic they act as bridges. 

Note:
-  After giving every switch the vlans in the network we must now make every port that connects to the core switch a trunk port thats connected to the core switch
- Also enabling the core switch port that connected to all switches and to the router as a trunk port. So every switch port interconnecting to the switches must be configured as a Trunk Port
Note: Ports connected directly to end devices (PCs, Server,AP,Printers) remain an access port

Next we created the ROAS and split the port connecting the router and switch into their respected vlans
enable
config t
interface g0/0/0
no shutdown
(This is to change the port to up, bringing up the physical link between the router and Core SW)
interface g0/0/0.10
(g0/0/0.10 now we created virtual subinterface 10 on the trunk port and to configuring it for vlan 10 traffic)
encapsulation dot1q 10
(Any frame that needs to be in vlan 10 will be given their 802.1q tag as vlan 10, so tells the router to tag outgoing frames with 802.1q vlan id 10 and accept incoming frames with vlan id 10)
ip address 192.168.10.1 255.255.255.0
(This tells where the vlan is going to be in the network so we know 192.168.10.x will be in vlan 10 it acts as the default gateway for devices in the subnet)
And so on for every vlan
